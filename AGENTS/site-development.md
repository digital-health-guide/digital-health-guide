# Site development

The site lives in `digital-health-guide.github.io/` (SvelteKit + adapter-static, Lily Design System, pnpm). Its `README.md` is the full reference; this is the working summary.

## Commands (run in the site directory)

```sh
pnpm install
pnpm run dev
BOOK=.. pnpm run sync     # vendor locales/ + reference docs into content/
pnpm run build            # vite build, search index, llms.txt/llms.json -> build/
pnpm run llms             # rewrite the repo-root llms.txt and llms.json
pnpm run sync:lily        # re-vendor Lily from ~/git/lilydesignsystem/lily-design-system
```

## Rules

- `content/` is generated from `locales/`; never edit it by hand. Re-sync after any book change.
- `src/lib/lily/` and `static/themes/` are vendored. Do not edit; change Lily upstream, re-sync, and record the commit in `src/lib/lily/VENDOR.md`.
- Routes: every locale is served under `/<locale>/`; `/` is a client-side redirect unless the URL carries a search query (`/?<target>`). Two-letter aliases (`/es/…`) render the world locale's page. Retired locales (`de-de`, `hi-in`, `ja-jp`, `zh-cn`) and old `/chapters/…` URLs redirect.
- A topic is any `<locale>/<dir>/<NN-NN-slug>/index.md`; its number comes from the slug prefix.
- UI strings live in `src/lib/strings.js`, one table per locale; add every key to every locale.
- The repo-root `llms.txt` and `llms.json` are committed copies of the generated files, for agents browsing the repository. Run `BOOK=.. pnpm run sync && pnpm run llms` after any change to a locale's Contents and commit the result.
- Search follows `spec/search/`; `/sitemap.xml` follows `spec/sitemap/` (per-URL `hreflang` alternates); `llms.*` are generated by `scripts/build-llms.mjs`.
- Canonical, `hreflang` and sitemap URLs are percent-encoded (`encodeURI`); redirect locations must be ASCII.
- Contents rendering follows `spec/contents-for-global-sharing-with-svelte/`: nested list, no tiles, tables, grid or flexbox.
- Use the Svelte MCP tools (`svelte-autofixer`, docs) for Svelte changes.

## Dependencies

`pnpm update --latest`, then `pnpm install --frozen-lockfile` and a full build. Keep `packageManager` in `package.json` in step with the installed pnpm, and update the action versions in `.github/workflows/deploy-site.yml` together.
