# AGENTS.md

Working instructions for AI agents in this repository. The specification in `spec/index.md` is the source of truth; where this file or any other artifact disagrees with it, the spec wins.

## What this repository is

*Digital Health Guide*: a practical handbook of best practices for delivering digital services in health and social care, written as Markdown in 14 locales, plus the SvelteKit site that publishes it at <https://digital-health-guide.github.io/>.

## Layout

| Path | What it is |
|---|---|
| `locales/<locale>/index.md` | Locale home page and table of contents (`README.md` is a symlink to it). |
| `locales/<locale>/<topics-dir>/PP-CC-slug/index.md` | One topic (73 topics plus the preface `00-01-…`). The directory name and slug are translated per locale; the leading `PP-CC-` number is shared by all locales and is what links translations together. |
| `locales/<locale>/.locale-peer-id` | 32-hex id, identical across locales for the same page. |
| `GLOSSARY.md`, `INDEX.md`, `STYLE_GUIDE.md` | Shared English reference matter. |
| `spec/` | Specifications: `index.md` (the book), `search/`, `sitemap/`, `contents-for-global-sharing-with-svelte/`, `locales-for-global-sharing-with-svelte/` (with `locales.tsv`), `oxford-spelling.md`. |
| `digital-health-guide.github.io/` | The site: SvelteKit + adapter-static, Lily Design System, pnpm. Its own `README.md` documents it. |
| `.github/workflows/deploy-site.yml` | Builds the site and publishes `build/` to the `gh-pages` branch of the `digital-health-guide.github.io` repository. |
| `_sources/` | Raw grounding material, not published. |

Locales: ar-001, bn-001, cy-001, de-001, en-001, en-gb (default, the source edition), en-gb-oxendict, en-us, es-001, fr-001, hi-001, ja-001, ru-001, zh-001. English locales use `topics/` and English slugs; the others use translated names (e.g. `es-001/temas/01-00-introducción/`).

## Guides

Task-focused guides live in [`AGENTS/`](AGENTS/README.md): authoring topics, translating locales, renumbering, site development, verification, and release and deploy.

## Conventions

- **Terminology:** the book's units are **topics**, not chapters. Contents labels follow the contents spec: parts are `N Title`, topics are `N.M Title`, as a nested list (no tiles, tables, grid or flexbox).
- **Authoring:** follow `STYLE_GUIDE.md` and spec §3 (the 13-section topic template). Cite only real, verifiable sources; never invent citations, URLs, statistics or Wikipedia slugs. Keep proper names, external titles and URLs untranslated.
- **Spelling:** en-gb uses British spelling; en-gb-oxendict uses Oxford `-ize`; en-us American; see `spec/oxford-spelling.md`.
- **Translations:** edit a locale's files only for that locale; keep headings, numbering and structure identical across locales. When you add or rename a topic, change every locale in one pass and follow spec §11 (decide the manifest first, back up, remap once).
- **Specs first:** change the spec deliberately, then bring the artifacts in line. Do not leave a spec and its implementation disagreeing.
- **Symlinks:** `README.md` → `index.md` in locales, topic folders and `spec/`. Edit `index.md`; never replace the symlink with a copy.

## Working on the site

Run everything inside `digital-health-guide.github.io/` with **pnpm**:

```sh
pnpm install
pnpm run dev
BOOK=.. pnpm run sync     # re-vendor the book into content/ (BOOK defaults to a sibling checkout that does not exist here)
pnpm run build            # vite build + search index + llms.txt/llms.json -> build/
pnpm run sync:lily        # re-vendor Lily (reads ~/git/lilydesignsystem/lily-design-system)
```

- `content/` is a vendored copy of the book; refresh it with `BOOK=.. pnpm run sync` after any change under `locales/`. CI does this itself.
- `src/lib/lily/` and `static/themes/` are vendored from Lily. Do not edit them; change Lily upstream and re-run `sync:lily`.
- Topic routes are derived from `<locale>/<dir>/<NN-NN-slug>/index.md`; the topic number comes from the slug prefix. Old `/chapters/…` URLs redirect to the topic pages.
- `build/llms.txt` and `build/llms.json` (and the committed copies `llms.txt` and `llms.json` at the repo root) are generated by `scripts/build-llms.mjs` from each locale's Contents; do not hand-edit. Refresh the root copies with `pnpm run llms` after Contents change.
- Verify changes with a full `pnpm run build` and check that internal links on the built locale home pages resolve.

## Git and deployment

- Commit signing is enabled in this environment; if a commit hangs on a signing prompt, ask the user to commit. Do not disable signing.
- Pushes go to both GitHub and GitLab remotes. Pushing `main` triggers the site deploy, which needs the `SITE_DEPLOY_KEY` secret and the site repository's Pages source set to the `gh-pages` branch.
- Never delete or overwrite a user's files without looking at them first; prefer `git mv` for renames so history follows.
